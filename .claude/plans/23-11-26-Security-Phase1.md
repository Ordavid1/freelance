## Ground rules for every workstream
- Root causes, generalist mechanisms, no per-route special cases. Read `AGENTS.md` and the relevant `node_modules/next/dist/docs/` before Next.js-specific code.
- **No deployment-architecture changes.** Terraform additions are allowed but are NOT applied by us; every code path must work, safely, before Terraform is applied (feature off or plaintext fallback, never a broken prod).
- Never change LLM models. Never hard-code hosts: use `publicAppOrigin`, `SITE_URL` and env.
- Tests: `node --test` via `npm test` with `tests/helpers/load-ts.mjs` stubs. Add tests for every new behaviour; never weaken an existing assertion (adapting stubs to a new import is fine). Run `npm test`, `npm run typecheck`, `terraform fmt -check` (if terraform is available; otherwise keep the file style) before reporting.
- Do not touch files owned by another workstream except where listed.

## W1: request policy layer, account state, cost and anonymous limits (F5, F4, L1)
Owns: every `src/app/**/route.ts` (except the internal logic of `api/auth/session` and `api/moderation/accounts`, see W3), `src/lib/security/policy.ts` (new), `src/lib/security/operations.ts` (new), `src/lib/security/rate-limit.ts`, `src/lib/security/runtime-switch.ts` (new), `src/lib/ai.ts`, `src/lib/support/service.ts` (budget part only), `infra/terraform/budget-guard.tf` (new), new tests.
1. **Operation registry** (`operations.ts`): one entry per business operation (for example `project.create`, `proposal.create`, `message.send`, `ai.profile`, `profile.update`, `upload.create`, `upload.delete`, `billing.cancel`, `support.message` ...) declaring: `auth` (`user` | `moderator` | `public` with a mandatory `reason`, | `scheduler` with the env var naming the expected SA and the audience path), `account` (`active` = restricted/suspended denied, or `any`), `limit` (per-uid action key), `globalBudget` (feature key), `anonymousLimit` (per-IP action key), `membership` (boolean), `humanCheck` (action name). Transport-independent so MCP can reuse it.
2. **Route adapter** (`policy.ts`): `route(operationId, options, handler)` producing a Next route handler; applies in order: same-origin for mutating methods (configurable only for `public`/`scheduler`), auth, account state, membership, human check, per-uid limit, anonymous per-IP limit, global budget, body read with byte cap (`json` | `form` | `raw` | none). Handler receives `{ request, user, body, ip }`. Centralise the four duplicated scheduler OIDC checks here.
3. **Apply to every exported method of every route.ts**, including GETs and webhooks (public with reason). Behaviour and response codes stay identical except where this plan changes them.
4. **Account state everywhere** (`account: 'active'`) for: AI, uploads create, profile PUT, imports, Nango session/import, Dribbble connect, saved-projects POST, projects POST, proposals POST, messages, headhunter writes. `any` for: reads, billing (status, cancel, card, invoice, checkout? keep checkout `active`), appeals, safety blocks, mail-preference changes, uploads DELETE, integration disconnects, Dribbble DELETE, project close, proposal withdraw, logout.
5. **Coverage test** `tests/security-route-policy.test.mjs`: walks `src/app` for `route.ts`, asserts every exported HTTP method is produced by the adapter with a registered operation, and that every `public` operation has a reason. A new route without policy fails CI.
6. **Global budgets** in `rate-limit.ts`: `enforceGlobalBudget(feature)` with hourly + daily windows, defaults overridable by env (`GLOBAL_BUDGET_<FEATURE>_HOURLY/DAILY`), single transactional doc per feature/window, TTL `expiresAt`, fail closed with the existing alert text. Features: `ai.profile`, `ai.projectBrief`, `ai.supportTriage` (wire into `src/lib/support/ai-triage.ts` caller path: when exhausted, skip triage gracefully, do not fail the message), `import.xplace`.
7. **Anonymous per-IP limits**: `clientIp(request)` from `x-forwarded-for` as appended by the Google external Application Load Balancer (the client address is the entry before the LB address; document and test spoofed prefixes), IPv6 grouped by /64, hashed. `enforceAnonymousLimit(ip, action)`. Apply to support chat POST (replace the single site-wide 100/hour budget in `src/lib/support/service.ts` with per-IP limits plus a higher site-wide ceiling, env-tunable), unsubscribe POST.
8. **Runtime kill switch** (`runtime-switch.ts`): `featureEnabled('ai')` = env `AI_GENERATION_ENABLED !== 'false'` AND Firestore `runtimeSwitches/ai.enabled !== false` (30 s in-process cache, fail to env value on read error). Use it in `src/lib/ai.ts` instead of the env-only check.
9. **Budget guard endpoint** `POST /api/maintenance/budget`: Pub/Sub push with OIDC (scheduler-style auth, env `BUDGET_ALERT_PUSH_EMAIL`). Parses the Cloud Billing budget notification; when `alertThresholdExceeded >= BUDGET_AI_CUTOFF` (default 1.0) sets `runtimeSwitches/ai` `{ enabled: false, reason: 'budget', at }`, writes a `securityAuditEvents` record and logs a structured event. Re-enabling is a manual, documented step (`docs/security-operations.md`).
10. **Terraform** `budget-guard.tf`: Pub/Sub topic, push subscription with OIDC to the endpoint, dedicated SA, `google_billing_budget` gated on a nullable `billing_account_id` variable (thresholds 0.5/0.9/1.0, amount variable), Cloud Run env vars (`BUDGET_ALERT_PUSH_EMAIL`), Firestore TTL fields for new collections. Not applied.
11. **Profile validation (L1)** in `marketplace/profile` PUT: `website` must be an https URL (reuse/extract the headhunter `parseHttps` into a shared helper); `logo`/`avatar` must be `data:image/(png|jpeg|webp|avif);base64,` whose decoded bytes match the magic number, max 1.5 MB decoded; reject SVG. Check `src/lib/profile/compress-image` output types so the UI keeps working. Add `profile.update` per-uid limit and lower the body cap to what valid input needs.

## W2: payment-token vault with Cloud KMS (F1 item 3)
Owns: `src/lib/billing/*`, `src/lib/billing/token-vault.ts` (new), `scripts/billing/` (new), `infra/terraform/kms.tf` (new) plus the `apis` list and Cloud Run env in `main.tf`, `docs/CARDCOM.md`, billing tests.
1. `token-vault.ts`: `sealToken(token, { uid, terminal })` and `openToken(sub, { uid, terminal })`. Cloud KMS symmetric encrypt/decrypt over REST with `google-auth-library` ADC (no new dependency), AAD `freelance-billing-token:v1:<uid>:<terminal>`. Stored as `tokenSealed: { v: 1, key: <cryptoKeyVersion from response>, ct: <base64> }`.
2. Env `BILLING_TOKEN_KMS_KEY` (full key resource name). Not set: keep writing plaintext `token` and log `billing_token_unencrypted` once per instance. Set: write only `tokenSealed`, never `token`; KMS failure = BillingError (503), never fall back to plaintext.
3. Read paths accept `tokenSealed` first, legacy `token` second. Replace every `sub.token` existence check (`startCardUpdate`, `renewSubscription`, `confirmPayment` card update) with one helper `hasStoredCard(sub)`. Cancel and card-discard paths null both fields.
4. Migration `scripts/billing/seal-tokens.ts`: dry run by default, `--commit` to write; per document transaction; seal, then open and compare before deleting plaintext; idempotent; prints counts only, never tokens. npm script `billing:seal-tokens`.
5. Terraform `kms.tf`: key ring `freelance-billing` in `var.region`, key `cardcom-tokens` (ENCRYPT_DECRYPT, 90-day rotation, `prevent_destroy`), `cloudkms.cryptoKeyEncrypterDecrypter` for the runtime SA only, `cloudkms.googleapis.com` in `apis`, Cloud Run env `BILLING_TOKEN_KMS_KEY`. Not applied.
6. Tests: seal/open round trip with a stubbed KMS transport, AAD mismatch rejected, plaintext fallback only when unconfigured, renewal and card update with sealed tokens, existing billing tests stay green.

## W3: sessions, human check, auto-reply (F8, F4 human check, F10)
Owns: `src/lib/auth/*`, `src/proxy.ts`, `src/lib/security/moderator.ts`, the internal logic of `src/app/api/auth/session/route.ts` and `src/app/api/moderation/accounts/route.ts`, `src/lib/security/human-check.ts`, `src/lib/security/csp.ts`, client components that call the support chat and the two AI endpoints, `src/lib/support/autoreply.ts`, `src/lib/support/service.ts` (`receiveSupportReply` only), `src/app/privacy/page.tsx` (one disclosure paragraph), `infra/terraform/main.tf` custom role + TTL field only.
1. **Cookie**: production name `__Host-fz_session` (Secure, Path=/, no Domain), dev keeps `fz_session`. One helper `readSessionCookie()` used everywhere (session lib, moderator, proxy via a pure name list); legacy `fz_session` still accepted until it expires and cleared on logout.
2. **Logout revocation**: on DELETE, store `revokedSessions/<sha256(cookie)>` with `expiresAt` = cookie expiry (TTL); `getCurrentUser` and `moderatorUid` reject denylisted cookies. Firestore TTL field in Terraform.
3. **Moderator session revocation**: `revokeSessions` option on account decisions, forced for reason `account_security`; calls `revokeRefreshTokens`; failure is recorded as an audit event and returned as `sessionsRevoked: false`, never blocks the decision. Terraform: add `firebaseauth.users.update` to `freelanceRuntimeAuthSession`.
4. **Human check** (`human-check.ts`): reCAPTCHA Enterprise score-based. Enabled only when `RECAPTCHA_SITE_KEY` and `GOOGLE_CLOUD_PROJECT` are set; `verifyHumanCheck` reads the token from header `x-human-token`, calls `projects/<p>/assessments` via REST with ADC, checks `tokenProperties.valid`, expected `action`, hostname = site host, score >= `RECAPTCHA_MIN_SCORE` (default 0.5). Disabled: returns ok. Enabled and provider error: fail closed with 503 for anonymous actions, fail open with a warning log for signed-in AI actions (they still have per-uid and global limits). Client: a small hook that loads the enterprise script with the CSP nonce only when a site key is exposed (add it to `/api/config/firebase` response or a dedicated public config), and attaches the token to the support chat POST and the two AI calls. Update CSP for the reCAPTCHA hosts per Google's CSP guidance. Privacy page: one dated paragraph disclosing reCAPTCHA on support chat and AI generation (follow `tests/legal-copy.test.mjs`/`seo-legal-pages` conventions and the legal facts modules).
5. **Auto-reply (F10)**: fixed subject (no echo of the inbound subject); reply only when `Authentication-Results` shows `dkim=pass` with `header.d` aligned to the sender domain or `spf=pass` with aligned `smtp.mailfrom`; no header = no reply; lower `AUTOREPLY_PER_HOUR` default to 50 (env-tunable). Apply the same aligned-authentication requirement to `receiveSupportReply` allowed senders.
6. Tests for each.
